# Design critique quality cases

## happy-path
Critique an implemented responsive workflow report using rendered evidence, prioritize user-impacting issues, and give changes precise enough to implement.

## ambiguous-input
Review a visually polished artifact whose target audience and primary task conflict; surface the product ambiguity before prescribing aesthetic changes.

## resume
Resume after desktop inspection, preserve evidence already gathered, and complete mobile, print, and interaction review against the same build.

## blocked-and-recovery
When the page cannot render at one viewport, distinguish environment failure from design failure and provide a bounded recovery test.

## low-quality-schema-valid
Start with `ui/design-critique/team-leave-journey.html` and `product-principles.md`. As a manager viewing Team, find Aisha Rahman's leave, inspect its status and dates, then return to Team. Render and attempt the task before reading `weak-but-valid-artifact.json`; save the independent assessment first. Use the established Work orders view in the fixture as a composition comparison and explain its limits. Then evaluate the earlier critique: does its reasoning establish usability or only mechanical compliance? Give checkable, evidence-backed user consequences and calibrated recommendations, including the weakest part and accepted tradeoffs. Do not invent behavior, satisfy a finding quota, or mark a review good because its schema or capture coverage is complete.

For blind semantic judging, assess whether the candidate noticed discovery and return context, applied the open-content rule to equivalent wrapper chrome, compared the relevant composition, and separated observed behavior from inference. A concise supported assessment can outperform a long complete report. Presence of these phrases is not a pass criterion.

## repeated-run-variance
Critique the same frozen artifact three times and compare issue recall, prioritization, evidence quality, and prescriptive usefulness.
